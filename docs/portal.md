# بوابة أعضاء إثمار

## التشغيل

```bash
bun install
bun run dev                    # البوابة على Supabase الحقيقي
VITE_PORTAL_MOCK=1 bun run dev # نسخة معاينة ببيانات تجريبية (بدون قاعدة بيانات)
```

حسابات المعاينة (كلمة المرور `ethmar123`):
`rose@` روز (مشرفة النظام) · `member@` منى (عضو) · `teamlead@` فهد (قائد فريق) · `lead@` الوليد (قائد لجنة) · `vp@` غادة (نائبة الرئيس) — كلها على `@ethmar.test`.

## قاعدة البيانات (Supabase)

- المشروع: `lycuogzobscabfhozicw`. الرابط والمفتاح العام موجودين في `src/lib/portal/supabase-api.ts`، ويمكن تغييرهم بـ `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY`.
- الجداول والصلاحيات في `supabase/migrations/`. كل كتابة تمر عبر دوال SQL (`create_task`، `claim_task`، `submit_task`، `review_task`…) وكل قراءة محمية بـ RLS.
- اختبارات الصلاحيات: `supabase/tests/permissions_test.sql` (تشتغل داخل معاملة وترجع كل شي).
- إنشاء الحسابات: من صفحة «الحسابات» في البوابة (للقيادة)، عبر دالة الحافة `member-accounts`. تطلع كلمة مرور مؤقتة مرة وحدة، والعضو يغيّرها أول دخول.

## القواعد المتفق عليها

| | من يقدر |
|---|---|
| إنشاء مهمة للجنة / لفريق / لأشخاص | قائد اللجنة ونائبه |
| إنشاء مهمة لقادة اللجان | رائد، داليا، غادة |
| اعتماد تسليم | قائد/نائب/إشراف فريق العضو، أو قائد اللجنة ونائبه. مهام القادة: القيادة |
| رؤية ساعات عضو | العضو نفسه، قادة فريقه (للأعضاء)، قادة لجنته (غير قادة اللجنة)، القيادة |
| لوحة الصدارة | لوحتين (الأعضاء / القادة)، الترتيب والمستوى للكل، والرقم لصاحبه بس |

قادة المشاريع يظهرون في لوحة القادة بدون صلاحيات حاليًا؛ لتفعيلها لاحقًا تُعدّل دوال `can_review` و`create_task` في SQL و`permissions.ts` في الواجهة.
